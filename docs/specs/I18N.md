# I18N — Hợp đồng "common" song ngữ VI/EN (``namios_i18n``)

**Trạng thái:** DESIGN (pha nâng cấp 03/11/2026) + đã hiện thực ``namios_i18n`` (Translator/catalog/test).
**Phạm vi:** lớp COMMON dùng chung toàn hệ thống cho MỌI chuỗi human-facing. KHÔNG đổi hành vi machine field.
**Sở hữu:** `namios_i18n` (package + `locale/*.json` + `docs/specs/I18N.md` này) — chỉ vai trò này sửa 3 nhóm file đó.

> Phân loại: **FACT** = bám đặc tả (VN-001..005, M1-INTERFACES CLI-001). **DESIGN** = quyết định của đợt nâng cấp này. **TARGET** = chỉ tiêu cho pha wire sau.

---

## 1. Vì sao có lớp này

Chỉ đạo chủ dự án (03/11/2026): (1) có lớp COMMON dùng chung để sửa một chỗ áp dụng mọi nơi; (2) song ngữ VI/EN toàn hệ thống, tiếng Việt vẫn phải chín chữ (đúng, tự nhiên, không máy dịch cứng); (3) không phá vỡ 800 test đang XANH.

`namios_i18n` giải quyết (1) và (2) bằng một `Translator` + 2 file catalog (`locale/vi.json`, `locale/en.json`) dùng key ổn định; (3) được bảo đảm bằng nguyên tắc: **catalog `vi` giữ NGUYÊN VĂN chuỗi tiếng Việt hiện có trong code** tại thời điểm quét — pha sau khi "wire" (thay lời gọi `print`/literal bằng `namios_i18n.t(key)`) sẽ không làm test cũ (so sánh chuỗi VI cứng) bị vỡ.

## 2. Hợp đồng bắt buộc cho MỌI module khác

- Mọi chuỗi **human-facing** mới (CLI help, `message_vi`/`reason_vi`, label UI, warning hiển thị người đọc) **PHẢI** đi qua `namios_i18n.t(key, **params)` thay vì literal string rải rác trong code.
- **Machine field KHÔNG dịch**: `ErrorBody.code` (`ErrorCode` enum), `Envelope.status`, exit code (0-9), tên khóa JSON (`"status"`, `"data"`, `"error"`, ...), `PublishedStatus`/`TxState`/`CompatStatus`/... giá trị enum chuỗi ổn định. Những trường này giữ nguyên giá trị bất kể ngôn ngữ hiển thị — đây là hợp đồng dữ liệu liên-module (M1-INTERFACES §1-§5), đổi theo ngôn ngữ sẽ phá mọi consumer.
- Tên key **ổn định**, không đổi sau khi phát hành (giống `ErrorCode`/`PublishedStatus`) — đặt theo mẫu `"<module>.<khu vực>.<chi tiết>"`, toàn chữ thường, dấu `.` phân cấp (xem §4).
- VI là ngôn ngữ **mặc định** (FACT VN-001) khi không có chỉ định nào khác — không module nào được tự đổi mặc định sang EN.

## 3. API (`namios_i18n`)

```python
from namios_i18n import Lang, t, add_catalog, resolve_lang, has_key, get_default_translator, Translator

Lang.VI  # "vi" — mặc định
Lang.EN  # "en" — song song

resolve_lang(explicit=None)
# Thứ tự ưu tiên: explicit (tham số/--lang) > biến môi trường NAMIOS_LANG > DEFAULT_LANG (VI).
# Không bao giờ raise — giá trị không nhận diện được (env hỏng, string lạ) rơi về VI.

t("cli.main.error.manifest_load_failed")                  # VI mặc định
t("cli.main.error.manifest_load_failed", lang=Lang.EN)     # ép EN
t("cli.main.error.service_not_found", id="thue.htkk")      # có tham số format

add_catalog(Lang.VI, {"my_module.greeting": "Xin chào {ten}"})  # module khác góp key riêng
add_catalog(Lang.EN, {"my_module.greeting": "Hello {ten}"})

has_key("cli.main.error.unknown_command", Lang.VI)  # True/False — dùng cho test parity riêng của module khác
```

Dùng `Translator()` (instance riêng, không phải singleton mặc định) khi cần cô lập hoàn toàn trong test (không ảnh hưởng tới `add_catalog` của module khác đang chạy song song).

### 3.1 Đổi ngôn ngữ

- **Biến môi trường**: `NAMIOS_LANG=en namios doctor --json` (hợp đồng cho mọi CLI subcommand khi wire ở pha sau).
- **Tham số rõ ràng**: hàm/lệnh có thể nhận `lang: Lang | str | None` và truyền trực tiếp vào `t(..., lang=...)` — ưu tiên cao hơn biến môi trường (vd cờ `--lang` CLI tương lai, hoặc setting người dùng đã lưu).
- Không có cấu hình nào đổi mặc định **toàn hệ thống** khỏi VI; "mặc định VI, chọn EN" là một chiều.

### 3.2 Format tham số — an toàn, không injection

`t()` dùng `str.format_map` với một `dict` phụ: tham số **thiếu** → chèn chuỗi rỗng (không `KeyError`); tham số **thừa** → bỏ qua (không lỗi); template catalog hỏng (dấu `{`/`}` không khớp, index vị trí không tồn tại) → trả nguyên văn template, **không crash** luồng gọi. Giá trị tham số luôn được chèn dưới dạng văn bản thuần (không `eval`, không nội suy lại thành format-spec mới) — không có đường injection nào qua tham số người dùng.

Muốn literal dấu `{`/`}` trong một chuỗi (vd tập giá trị hợp lệ `{telex, vni}`), escape bằng `{{`/`}}` trong catalog JSON — giống quy ước `str.format` chuẩn của Python (xem `welcome.firstrun.error.ime_method_invalid`).

### 3.3 Fallback khi thiếu key

Thứ tự tra cứu của `t(key, lang=L)`: `L` → `vi` (nếu `L != vi`) → `en` (nếu `L != en`) → chính `key` (trả nguyên văn, không raise). Luôn có chuỗi hiển thị được, không bao giờ `KeyError` ra tới UI/CLI.

## 4. Quy tắc đặt key

`"<module>.<khu vực>.<chi tiết>"`, toàn chữ thường, dùng `_` nối từ trong mỗi đoạn, `.` phân tách cấp. Ví dụ đã seed từ đợt quét 03/11/2026 (`locale/vi.json`/`en.json`):

| Tiền tố | Nguồn | Ví dụ key |
| --- | --- | --- |
| `cli.parser.*` | `namios_cli/parser.py` (help text argparse) | `cli.parser.cmd.doctor_help` |
| `cli.main.*` | `namios_cli/main.py` (error/not-wired/render) | `cli.main.error.manifest_load_failed` |
| `eco.status.reason.*` | `namios_eco/status.py` (lý do suy ra published_status) | `eco.status.reason.not_inventoried` |
| `eco.workflow.error.*` | `namios_eco/workflow.py` (lỗi kết cấu 7 nấc) | `eco.workflow.error.step_order` |
| `eco.validator.error.*` | `namios_eco/validator.py` (lỗi ngữ nghĩa ECO-003/006/007) | `eco.validator.error.usability_claim_forbidden` |
| `eco.catalog_schema.error.*` | `namios_eco/catalog_schema.py` (lỗi tầng 1) | `eco.catalog_schema.error.string_length` |
| `welcome.ui.*` | `namios_welcome/ui.py` (label/title wizard PySide6) | `welcome.ui.migrate.status_label` |
| `welcome.firstrun.error.*` | `namios_welcome/firstrun.py` (`reason_vi` validate) | `welcome.firstrun.error.field_blank` |
| `welcome.migrate.error.*` | `namios_welcome/migrate.py` (`reason_vi` skip/conflict) | `welcome.migrate.error.io_error_copying` |

`namios_doctor` không có chuỗi human-facing riêng ngoài help text đã nằm ở `cli.parser.cmd.doctor_help` (payload `doctor --json` chỉ có machine field — xem `namios_doctor/doctor.py`).

Khi thêm key mới (module khác, pha wire sau):
1. Không tái dùng key đã publish cho nghĩa khác — coi key như hợp đồng ổn định (giống `ErrorCode`).
2. Giá trị `vi` lúc seed PHẢI đúng ký tự với chuỗi literal hiện có trong code (không tự "cải thiện văn phong" trong lúc wire — sửa văn phong là một thay đổi tách riêng, có review).
3. Luôn thêm cả `vi` và `en` cùng lúc (test parity `tests/unit/i18n/test_catalog_parity.py` chặn thiếu một bên).
4. Dùng `add_catalog()` để góp key riêng của module — **không** sửa trực tiếp `namios_i18n/locale/*.json` (sở hữu bởi `namios_i18n`).

## 5. Phạm vi đợt này (TARGET cho pha sau)

Đợt 03/11/2026 chỉ **seed catalog nguồn** (quét chuỗi hiện có, gán key, viết bản EN tương đương) + hạ tầng `Translator`/test. **CHƯA** thay literal string trong `namios_cli`/`namios_eco`/`namios_welcome` bằng lời gọi `t(...)` — đó là bước "wire" ở pha sau, để không đổi hành vi/test hiện có trong cùng một đổi mới rủi ro cao. `namios_i18n/locale/*.json` là NGUỒN để bước wire tham chiếu đúng key, không phải đã có hiệu lực runtime trong các module đó.

## 6. Test bắt buộc (`tests/unit/i18n/`)

- `test_resolve_lang.py` — thứ tự ưu tiên explicit/env/default; chuẩn hoá hoa-thường/khoảng trắng; giá trị lạ rơi về VI.
- `test_translator_t.py` — VI mặc định; ép EN qua tham số/env; chuỗi VI hiện có giữ nguyên y hệt; format tham số an toàn (thiếu/thừa/escape `{{}}`); fallback vi/en khi key chỉ có một bên; template hỏng không crash; `add_catalog` góp key mới + override cô lập theo instance.
- `test_catalog_parity.py` — `vi.json`/`en.json` tồn tại + parse được; mọi key có cả 2 bên; không giá trị rỗng; không key trùng lặp trong 1 file; `Translator` nạp đúng nguyên văn từ 2 file.

Chạy: `python -m pytest tests/unit/i18n -q`.
